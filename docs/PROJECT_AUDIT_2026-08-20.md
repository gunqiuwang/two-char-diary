## 3. 新发现问题（上轮审计未覆盖）

### P1

**A1. `project.config.json` 品牌残留**
`description` 仍写「二字日记 - 每天用两个字和一个爻卦记录当天」，与现行品牌「二字爻记」不一致。上传时该描述不影响审核，但会在开发者工具与导出包中残留旧名。

**A2. 年历年份无上下界**
`calendar.js` 的 `prevYear` / `nextYear` 不限制范围。农历数据表只覆盖 1900–2050（`LUNAR_INFO` 150 项），翻到 2051 年之后虽然不会崩溃（`loadDetail` 只对有记录的日期调农历换算），但年界面可无限翻页属于无效交互；若未来扩展「任意日期补记」功能会立刻踩到越界。建议年范围钳制在 1900–2050。

**A3. 基础库版本不满足 AI 升级要求**
当前 `libVersion: 3.15.0`。调用成长计划免费额度的 `createModel("cloudbase")` + `hy3` 组合要求基础库 **≥ 3.15.1**（见混元生文模型升级指南）。这是 v2.0 的硬前置，需在 `project.config.json` 与微信后台最低基础库设置中同步上调。

### P2

**A4. 海报高度估算用 `text.length`**
`share.js` 的 `estimateLineCount` 按 UTF-16 码元计数，emoji 等代理对字符会低估行数，极端情况下海报底部内容被裁。实际绘制用的 `wrapText` 是 `for...of` 正确实现。建议 `estimateLineCount` 改用 `Array.from(text).length`。

**A5. 无运行时错误监控**
全项目无 `wx.onError` / `wx.onUnhandledRejection` 收集。上线后无法感知真机异常。v2.0 接入云函数后建议至少加本地错误计数 + 云函数日志。

**A6. 年历 `parseInt` 未显式进制**
`calendar.js loadDetail` 中 `parseInt(y)` 等缺 radix 参数，当前输入受正则约束不会出错，属代码规范问题。

## 4. 分维度审计明细

### 4.1 架构与工程

- 原生 WXML/WXSS/JS，无构建链，163 KB 包体，无分包需求 —— 合理
- 纯前端 + 本地存储，无后端 —— v1 阶段合理，v2.0 需引入云开发
- `app.json` 未配置 `lazyCodeLoading: "requiredComponents"`，页面注入可再优化（P3）
- 无 ESLint/Prettier 配置，代码风格靠自律，目前一致性尚可

### 4.2 数据与存储

- 存储键 `diary_data`（记录）与 `settings`（设置）两个，结构清晰
- 单条记录约 300–600 字节，一年全勤 < 250 KB，远低于 10 MB 本地存储上限
- 无 schema version 字段；`saveHex` 用对象展开合并，向后兼容尚可，但缺正式迁移机制
- `clearData` 有二次确认，清除范围说明准确

### 4.3 核心算法

- **起卦**：`genYao` 三币模型概率分布正确；`Math.random` 对文化注脚场景可接受
- **卦象查表**：`getHex` 以六爻自下而上拼二进制键，与 `HEX_DATA` 键序一致（64/64 校验通过）
- **农历**：查表法 1900–2050，春节、千禧年、闰月样例全部通过
- **节气**：固定公历日期 + ±1 天宽匹配，存在「非节气日显示节气名」的已知偏差

### 4.4 页面逻辑

- index：编辑态/起卦态定时器均有清理；跨午夜日期刷新已处理；连续天数统计无截断
- calendar：年月切换清空旧详情；空日期格 key 唯一；单层页面栈返回有兜底
- share：分享参数有校验与长度截断；Canvas DPR 封顶 2；生成竞态有 generation id；保存有并发锁与权限引导
- settings：设置合并写入不覆盖其他字段；概览统计口径与首页一致

### 4.5 安全与隐私

- 无 AppSecret、无业务域名、无网络请求，攻击面极小
- 唯一敏感权限：相册写入（用户主动触发，有拒绝引导）
- 分享 query 明文携带二字与卦象信息 —— 设计上知情取舍，v2.0 用云函数 share token 可根治

### 4.6 合规现状（v1）

- 《隐私保护指引》需与实际 API 一致（相册写入已声明即可）
- 文案坚持「文化注脚」定位，无预测承诺类表述 —— 保持
- **v2.0 新增合规面**（接入 AI 后必办）：
  1. 小程序类目需覆盖「深度合成 / AI 生成」相关要求，成长计划本身要求类目为文娱/工具/社交/深度合成/资讯类
  2. AI 生成内容需按《人工智能生成合成内容标识办法》做显式标识（如「内容由 AI 生成」角标）
  3. AI 输出需过内容安全（云开发提供安全检测能力，云函数侧先审后返）
  4. 隐私指引需新增「为生成 AI 注脚/插画，会将当日二字、卦名等发送至云开发 AI 服务」的说明
  5. 免费 AI 额度**仅限小程序端 `wx.cloud.extend.AI` 与云函数服务端调用**——不得把 `https://cloud1-...api.tcloudbasegateway.com/v1/ai/cloudbase` 网关地址拿到小程序/云函数之外直接 HTTP 调用（官方专项治理公告明确此为违规消耗）

### 4.7 性能

- setData 粒度可接受；纹理为内联 SVG data URI，无额外请求
- 163 KB 包体对启动无压力；Canvas 海报按需生成
- 升级后注意：AI 流式响应期间避免高频 setData（建议 200ms 节流合并）
