# 二字爻记 · 小程序修复验收标准

> 日期：2026-07-09
> 状态：历史验收记录；最新结论以 `PROJECT_AUDIT_2026-07-10.md` 和 `WECHAT_SUBMISSION_CHECKLIST.md` 为准。
> 范围：上线前第一轮修复，重点覆盖微信小程序配置、首页输入、起卦动效、分享链路、历史分享、数据备份与基础发布风险。

---

## 1. 基础构建验收

### 1.1 微信开发者工具编译

- 用微信开发者工具打开 `miniprogram` 目录。
- 编译类型应为小程序。
- 基础库版本应统一为稳定版 `3.15.0`。
- 编译面板不应出现 JS 语法错误、JSON 解析错误、页面路径不存在错误。

### 1.2 静态检查

已执行：

```bash
for f in $(find miniprogram -name '*.js' | sort); do node --check "$f" || exit 1; done
```

验收标准：输出 `JS syntax OK`。

已执行 JSON 解析检查。

验收标准：`app.json`、页面 JSON、`project.config.json`、`sitemap.json` 均可正常解析。

## 2. 发布配置验收

### 2.1 基础库版本

- `miniprogram/project.config.json` 与 `project.private.config.json` 中 `libVersion` 都应为 `3.15.0`。
- 不应再使用灰度基础库 `3.16.0`，也不应出现公开配置与私有配置版本分裂。

### 2.2 外部字体依赖

- `miniprogram/app.js` 不应再调用外部 CDN 的 CSS 字体地址。
- 项目中不应再出现 `cdn.bootcdn`、`style.css` 字体加载地址。
- 字体应优先使用系统字体、微信内置字体与 CSS 字体栈兜底。

### 2.3 sitemap

- 首页 `pages/index/index` 允许被索引。
- `share`、`calendar`、`settings` 不作为搜索索引页面。

## 3. 首页功能验收

### 3.1 二字输入

操作：

1. 打开首页。
2. 点击第一个米字格。
3. 输入一个汉字。
4. 输入焦点应自动跳到第二个米字格。
5. 输入第二个汉字。

验收标准：

- 两个字都正常显示在米字格中。
- 保存成功后出现“已记下”。
- `已记录 X 天` 数据应立即刷新，不需要退出页面再进入。

### 3.2 已记录后重新编辑

操作：

1. 当天已有记录时，点击任意米字格。
2. 观察灵感词区域。
3. 点击一个灵感词，或重新输入两个字。

验收标准：

- 点击米字格后，灵感词应稳定出现，不能闪一下后消失。
- 输入框能正常激活；即使个别机型键盘未立即弹出，灵感词也应保持可选。
- 点击“换一批”后提示词继续显示。
- 点击任意提示词后应立即替换两个字并保存。
- 能手动重新保存当天二字。
- 页面不应卡死或需要重复多次点击。

### 3.3 起课 / 起卦动效

操作：

1. 当天未起卦时，点击“起课”。

验收标准：

- 文案应从“起课”变为“成卦中”。
- 铜钱应出现约 1.2 秒的起卦动画。
- 动画结束后展示六条爻线、卦名、卦辞、爻辞。
- 起卦过程中重复点击不应触发多次生成。
- 当天已起卦后再次点击，应提示“今日已起卦”。

## 4. 分享功能验收

### 4.0 中文字体与乱码

操作：

1. 清除微信开发者工具缓存并重新编译。
2. 打开分享页。
3. 依次检查页面预览和保存到相册后的海报。

验收标准：

- 页面标题必须正确显示为“二字爻记”。
- “爻”、农历日期、卦名、卦辞、六条爻辞均不得出现错字、乱码或字符映射异常。
- Canvas 保存图片中的文字必须与页面预览一致。
- 项目中不得再出现 `WeChatSansSS` 或 `wx.loadBuiltInFontFace`。


### 4.1 首页进入分享页

操作：

1. 当天已记录二字并已起卦。
2. 点击首页底部“分享”。

验收标准：

- 应进入 `/pages/share/share?date=YYYY-MM-DD`。
- 分享页显示当天二字、农历日期、卦象、卦名、卦辞与爻辞。

### 4.2 分享给朋友

操作：

1. 进入分享页。
2. 点击底部“分享”。
3. 发送给好友。

验收标准：

- 分享标题应为 `今日二字：XX`。
- 分享路径应携带 `date=YYYY-MM-DD`，并携带二字、农历、卦名、卦辞、爻线等兜底 query 数据。
- 好友打开后应进入对应日期的分享页，而不是空首页。
- 即使好友本机没有你的 `diary_data`，也应能看到分享出来的二字和基础卦象信息。
- 如果 Canvas 临时图生成成功，分享卡片应使用该图片作为封面。

### 4.3 分享到朋友圈

操作：

1. 进入分享页。
2. 从右上角菜单分享到朋友圈。

验收标准：

- 标题应为 `今日二字：XX`。
- query 应携带 `date=YYYY-MM-DD`，并携带二字、农历、卦名、卦辞、爻线等兜底数据。
- 能打开对应日期分享页。
- 跨设备打开时，即使本地没有原始记录，也应展示基础分享内容。
- 若临时图已生成，应显示分享封面；未生成时不应影响基础分享。

### 4.4 保存图片

操作：

1. 进入分享页。
2. 点击“保存”。

验收标准：

- 能生成 Canvas 海报。
- 授权后能保存到相册。
- 拒绝相册权限时，应提示需要授权，并可打开设置。

## 5. 年历页验收

### 5.1 查看历史记录

操作：

1. 进入年历页。
2. 点击有记录的日期。

验收标准：

- 下方详情卡应显示该日二字、卦象信息与爻辞。
- 点击无记录日期时，应提示“当日暂无记录”。

### 5.2 历史记录分享

操作：

1. 在年历页选择一条历史记录。
2. 点击“分享”。

验收标准：

- 应进入 `/pages/share/share?date=选中日期`。
- 分享页显示的是选中日期的数据，而不是今天的数据。

### 5.3 年历单屏布局

操作：

1. 进入“记录”页。
2. 在常见全面屏和 667px 左右矮屏设备查看。
3. 点击一个包含完整卦象和六条爻辞的日期。

验收标准：

- 页面本身不应出现纵向滚动。
- 上半屏应完整显示年份、月份选择、星期和当月日期网格，并保留适度纵向呼吸空间。
- 所有月份统一使用 42 个日期格的六周结构，切换月份时月历高度不得跳动。
- 下半屏应沿用主页的内容顺序：日期信息 → 两个米字格 → 六爻线 → 卦名与卦辞 → 六条爻辞。
- 两个历史记录文字应分别显示在缩小版米字格中，比例和线条语言与主页一致。
- 六条爻辞应按主页式纵向列表完整显示，每条使用细分隔线，不使用两列大分栏。
- 六条爻辞不得使用 `flex: 1` 平均拉伸；常规屏单行高度约为 70rpx，矮屏约为 52rpx。
- 爻辞不得使用省略号截断，也不应依赖点击浮层才能阅读完整内容。
- 爻辞正文应正常横向换行，行间距应紧凑且一致，不得出现被强行拉大的空白单元格。
- 矮屏设备可以压缩字号和间距，但不得遮挡日期网格、完整爻辞或分享入口。

## 6. 设置页验收

### 6.1 背景切换

操作：

1. 进入设置页。
2. 切换宣纸、绢帛、竹简、素黑。
3. 回到首页、年历页、分享页。

验收标准：

- 背景样式应被保存。
- 各页面应同步使用新的背景风格。

### 6.2 动效减弱

操作：

1. 将动效从“标准”切换为“减弱”。
2. 依次打开首页、记录页、分享页和设置页。

验收标准：

- 设置应持久保存。
- 页面进入、循环装饰动画和过渡应明显减弱。
- 起卦、保存、分享等功能状态仍应正常完成，不得因减弱动效失效。

### 6.3 一屏布局与更多入口

验收标准：

- 常见全面屏中，设置页主体内容应在一屏内完整显示，不依赖纵向滚动。
- 背景卡片、动效行、数据概览和数据功能行应保持上一版正常比例，不得为适配一屏而整体缩小。
- 数据区应保留记录天数、起卦次数和最近记录的完整概览卡。
- “更多”中不再显示独立的“数据与隐私”入口。
- “分享小程序”和“关于二字爻记”应保留，并在删除前一入口后自然上移。
- 关于弹窗应继续说明本地存储、主动分享、换机/清缓存风险与当前版本。

### 6.4 清除数据

操作：

1. 进入设置页。
2. 点击“清除所有数据”。

验收标准：

- 二次确认弹窗应明确提示删除不可恢复。
- 确认后 `diary_data` 被清空。
- 回首页后不应再显示历史记录。

## 7. 真机验收建议

至少用以下设备/环境测试：

- iPhone 小屏或模拟小屏。
- iPhone 刘海屏 / 灵动岛机型。
- Android 微信最新版。
- 开启深色背景“素黑”。
- 网络断开状态。

验收标准：

- 断网时首页、记录、起卦、历史、设置仍可用。
- 不应因为外部字体加载失败影响页面展示。
- 自定义导航按钮不应被微信胶囊遮挡。
- 保存图片与分享功能在真机上可用。

## 8. WXML 静态中文编码验收

操作：

1. 打开分享页。
2. 检查页面标题、印章、空状态和底部操作文字。

验收标准：

- 标题必须显示为“二字爻记”。
- 印章必须显示为“爻”。
- 底部文字必须显示为“保存”“分享”。
- 不应出现“浜屽瓧”“淇濆瓨”“鍒嗕韩”等乱码。
- `share.wxml` 必须是 UTF-8 编码。
- 项目内 WXML 不应包含已知 mojibake 字符串。
