## 3. 本轮发现并修复的问题

### 3.1 首页逻辑

已修复：

1. **跨午夜日期不刷新**  
   之前页面常驻跨过 00:00 后，日期和灵感词仍可能是前一天。现在 `onShow` 会检测日期键变化并刷新公历、农历、节日和候选词。

2. **连续记录最多只统计 365 天**  
   已改为按实际记录数量计算，不再人为截断。

3. **已有二字难以直接替换**  
   已有记录进入编辑时，聚焦输入框会清空当前输入值，但米字格仍保留视觉文字，用户输入新字即可替换。

4. **编辑未完成时页面卡在编辑态**  
   用户输入不完整后失焦，会恢复已保存记录，不再长期隐藏分享入口。

5. **Unicode 字符被拆开**  
   统一使用 `Array.from` 处理字符，避免 emoji 或扩展字符被拆成 UTF-16 半字符。

6. **起卦定时器生命周期**  
   增加定时器引用和卸载清理；起卦结果保存到启动起卦时对应的日期。

7. **列表 key 不稳定**  
   卦线和爻辞循环使用稳定 key，减少渲染警告。

### 3.2 年历逻辑

已修复：

1. **切换年份或月份仍显示旧日期详情**  
   切换年月时清空旧选择和详情。

2. **记录加载与月份构建存在时序隐患**  
   `buildMonth` 现在在 `recordDates` 的 `setData` 回调后执行。

3. **日期网格 key 不唯一**  
   空白格和实际日期均生成唯一 key。

4. **直接打开页面时返回失效**  
   页面栈只有一层时改为 `reLaunch` 首页。

### 3.3 分享逻辑

已修复：

1. **接收者自己的记录覆盖分享内容**  
   有分享参数时优先展示分享数据；只有内部打开且无分享参数时才读取本地记录。

2. **外部分享打开后返回按钮无效**  
   单页栈时返回首页。

3. **分享页切换纸张意外修改全局主题**  
   纸张选择现在只影响当前分享卡；全局主题只在设置页修改。

4. **恶意或异常 query 可能导致异常**  
   日期格式、二字长度、卦名、卦辞和爻线均做校验和长度限制。

5. **Canvas 在高 DPR 设备上尺寸过大**  
   海报 DPR 最大限制为 2，避免超大画布和内存失败。

6. **重复生成分享图存在竞态**  
   增加 generation id 和定时器清理，旧任务不会覆盖新纸张生成结果。

7. **重复点击保存**  
   增加 `isSaving`，防止并发生成和重复权限请求。

8. **保存失败没有反馈**  
   权限拒绝引导去设置，其他失败显示重试提示。

9. **Canvas 字符索引**  
   使用 Unicode 字符数组绘制二字。

10. **分享页静态中文乱码**  
    `share.wxml` 已按 UTF-8 重写，项目验证脚本会扫描常见乱码模式。

### 3.4 设置与品牌一致性

已修复：

- `app.json` 默认标题由“二字日记”统一为“二字爻记”
- 保存设置改为合并旧设置，避免未来新增字段被覆盖
- 导出失败增加提示
- “数据不会上传”改成更准确的说明：默认本地保存，主动分享时内容会通过微信发送
- 返回按钮增加单页栈兜底

### 3.5 UI 和可访问性

已优化：

- 首页、分享页底部导航透明度提高
- 底部导航最小触控区域扩大
- 返回按钮、年份按钮、日期格、设置项、灵感词和起课按钮扩大触控区域
- 功能标签字号适度提高
- 关键交互添加 `aria-label`
- 内容区底部留白增加，降低与固定导航重叠的风险

## 4. 当前仍存在的风险

### P0：提审前必须人工确认

#### 4.1 微信后台隐私保护配置

代码使用：

- `wx.saveImageToPhotosAlbum`
- `wx.openSetting`

必须在微信公众平台检查《小程序用户隐私保护指引》是否与实际行为一致。不能只依赖“关于”弹窗。

建议说明：

- 日记记录默认只存储在用户本机
- 用户主动保存时访问相册写入能力
- 用户主动分享时，选中的二字和基础卦象信息通过微信分享

#### 4.2 服务类目和内容表述

建议定位：

- 工具 / 日历或效率
- 传统文化记录
- 情绪日记 / 灵感记录

避免文案：

- 算准未来
- 改运
- 保证吉凶结果
- 财运、疾病、婚姻等确定性预测

“起课”可以保留文化表达，但产品简介应明确卦象是每日记录的文化注脚。

#### 4.3 真机分享和权限

静态代码无法替代以下真机验证：

- iOS 保存相册首次授权、拒绝后再次授权
- Android 保存图片
- 好友分享的封面图和打开路径
- 朋友圈分享的 query 和封面图
- 接收者同一天已有本地记录时，仍显示发送者分享内容

#### 4.4 开发者工具质量检查

上传前运行：

- 代码质量
- 体验评分
- 真机调试
- 上传前预检

最终验收使用稳定基础库，不使用灰度基础库。

### P1：下一轮建议处理

#### 4.5 节气算法是简化版

`utils/solarterm.js` 使用近似固定日期，并把节气前后一天也识别成节气。可能出现“实际不是节气当天，但首页仍显示节气名称”的情况。

建议下一轮：

- 节气标签只在准确日期显示
- 推荐词可以单独支持“节气附近”
- 引入按年份计算或经过验证的 1900—2100 节气算法

#### 4.6 数据仅保存在本机

项目没有账号、云备份或跨设备恢复。清理微信缓存、删除小程序或更换设备后，本地记录可能丢失。设置页“关于二字爻记”已明确提示这一限制；若未来补恢复能力，应优先采用真正的云同步或文件备份，而不是剪贴板 JSON。

#### 4.7 分享 URL 暴露基础记录内容

为实现无后端跨设备分享，目前二字、农历、卦名、卦辞和爻线写入分享 query。这是用户主动分享，但内容可能出现在微信分享链路和日志中。

长期方案：使用云函数生成短期 share token，分享页通过 token 获取明确授权的快照。

#### 4.8 跨设备分享不包含完整六条爻辞

这是为控制 query 长度做的取舍。分享海报生成成功时图片包含完整爻辞，但接收者打开页面只看到基础卦象信息。

#### 4.9 自定义导航尚未使用胶囊坐标统一计算

当前基于状态栏高度布局，在现有模拟器截图正常。仍应测试：

- 小屏 iPhone
- 灵动岛机型
- Android 异形屏
- HarmonyOS 微信
- 大字体模式

需要时统一接入 `wx.getMenuButtonBoundingClientRect()`。

#### 4.10 本地数据缺少 schema migration

当前本地记录没有正式 schema version。未来修改记录结构时，应增加兼容读取或版本迁移，避免旧用户数据无法显示。
